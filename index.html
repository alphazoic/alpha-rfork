              Download

              4
              How many files in a folder download in parallel. Has no effect on single-file downloads. Default: 4.
              Files at or above this size are split into chunks, which are assembled after the download finishes. Smaller chunks give more resume checkpoints; larger chunks means fewer chunks.
              Method used when downloading in Stream Mode. Sparse files are more efficient but only work on Linux.
              MB
              Chunk size used in Stream Mode downloads. Range: 10–1000 MB. Default: 100 MB. Smaller chunks allow the media player to seek sooner; larger chunks reduce API round-trips. Stream Mode always uses 1 concurrent download regardless of the threads setting above.
              When enabled, the file opens in your default media player as soon as it is ready to stream. HTTP Proxy: opens when the head and tail chunks are buffered. Sparse File: opens when Watch in shows Now!. Disabled by default.

              Megatools Uploads

              These settings control how the bundled megatools fork uploads files. They have no effect when megacmd or rfork is used instead. They control the way that data in flight is organized and transferred. Mega breaks up files into small pieces, set by buffer size. Boost mode bundles these pieces together into chunks set by chunk size. These bundles are sent simultaneously by every worker.
              5
              Parallel upload threads. Range: 1–100. Each worker maintains its own HTTP connection. Default: 5. For me, anywhere 4-6 works. If you disable boost mode, you should increase this. More workers should be used for those with fast connections and high latency. Note: Using a VPN increases latency. Using too many workers can lead to instability and errors.
              Boost Mode Settings
              Determines how big the bundles of file chunks are. Like, worker threads, bigger sizes should be reserved for fast connections with high latency. Try increasing workers before increasing chunk size.
              curl internal send/receive buffer per worker. Larger buffers keep the pipe full on high-latency connections. Setting too high may waste memory. If boost mode is enabled, increase chunk size instead and leave this smaller.

              Megacmd Uploads

              Controls the number of parallel connections MEGAcmd uses when uploading a file. Has no effect when megatools or rfork is used instead. Unlike megatools, setting this too high will cause little to no issues.
              10
              Default: 10. Range: 1–100.
